# WP55: Planner route and drawer chip (V2)

Wires the Planner view (WP53) into the shell.

- `web/js/routes.js`: `planner` section between Roadmap and Work, module `./views/planner.js`, icon `planner`.
  The nav and the bottom bar read the registry, so no nav.js change was needed.
- `web/js/app.js`: calls the Planner's `bind(main)` once after its module loads; routes the Work drawer's
  "Link to feature" change event to `featureLinkChange` in details.js.
- `web/js/state.js`: `normalizeSnapshot` keeps the snapshot's `features` block (null when absent).
- `web/js/views/details.js`: a "Feature" section in the task drawer. Chips link to `#/p/<id>/planner?f=<id>`. A task
  with no feature gets a "Link to feature" select that runs `feature.link` with `{task, feats: [id]}`. The section is
  left out when the snapshot has no `features` block.
- `web/icons.svg`: one `i-planner` symbol.
- `tools/ui_smoke.py`: `planner` added to SECTIONS (same order as routes.js).
- `tests/web/test_planner_wire.py`: wiring checks, read from the files.

Known gap: the Planner does not yet open the feature named by `?f=` (planner.js is WP53's file and was not in this
package). The chip link lands on the Planner for that project.

Global scope: the nav entry shows in All projects; the view says "Planner belongs to one project." like Issues.
