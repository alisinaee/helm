# WP28: app shell and command layer

- `web/index.html`: the new shell (nav, top bar, main, the right panel `<aside class="side">` with its two tab stubs and a
  "Coming soon" body, bottom nav, toasts, the `?` help dialog). Links shell, panel, work, plan, admin and flow CSS.
- `web/css/tokens.css`: tokens for widths, heights, shadows, scrim, selection, drop target, z-index, `--t-fast` and
  `--unknown`, in the dark default and both light blocks. `web/css/shell.css` (grid, rail at 1199 px, bottom nav and
  sheet at 640 px). `panel.css`, `work.css`, `plan.css`, `admin.css`, `flow.css`: commented stubs for later packages.
- `web/icons.svg`: 16 original symbols (`i-*`), used through `<use href="/icons.svg#i-…">`.
- `web/js/router.js`: `#/all/<section>` and `#/p/<id>/<section>[/<view>][/i/<item>]`, filters in `?f=&g=`. Old `#/` and
  `#/p/<id>` links are replaced with their canonical form. `web/js/routes.js`: the section registry. A section with a
  null module shows "Coming soon" without a request; a module that fails to import does the same.
- `web/js/state.js`: UI preferences under `rb.ui.v2` (navMini, panelOpen, panelTab, workView, filters, density, theme,
  lastProject), every access in try/catch. The snapshot keeps `control` and `meters.limits`; missing meters read as
  unknown.
- `web/js/cmd.js`: `run(op, args, {apply, revert, label, project, key, value})` posts to `/api/v1/cmd` with the CSRF
  token. On failure it reverts and shows the server message. A reply with `undo: true` gets an Undo toast (5 s), which
  posts `undo` for that activity. `pendingValue()` keeps the Stop/Resume state until a later snapshot.
- `web/js/keys.js`: `[` nav, `]` panel, `z` undo, `?` help, `Esc`, and `g` then a letter for sections. Ignored while
  typing. `bindKey()` lets later views add keys.
- `web/js/views/nav.js`, `topbar.js` (crumb, Running/Stopped pill with one Stop/Resume button, Today and Week meters from
  `meters.limits`, connection dot, theme, `?`), `toast.js` (aria-live, hover and focus pause), `overview.js` and
  `work.js` (placeholders that mount the existing project and Home content; `views/home.js` links now use `#/all/overview`).
- `web/js/app.js`: boot and poll loop unchanged; the shell renders each pass, and the section module loads on first visit.
- Tests: `tests/web/test_shell.py` (sprite ids and size, CSS budgets, section registry, node render of the router, nav,
  bottom nav and top bar) with `tests/web/render_shell.mjs`.

## Gaps
- The right panel (Projects and Details) is a stub; PB builds it.
- Work, Overview and the other sections are placeholders over the existing content; later packages replace them.
- The top bar meter fill uses used/limit for the bar width only; the values come straight from `meters.limits`.
- Work badge counts tasks with `needsUser`, since the snapshot has no blocked state.
- Keys for items (j k Enter s x d h c and so on) are not bound yet.
