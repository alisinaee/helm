# WP21: command layer and CLI

- `roadmap/services/commands.py` (new): the registry (`OPS`) and `run(op, args, source, data_dir, now)`. Each call
  validates, runs the WP20 services, appends one activity line (`activity.append`) and returns
  `{ok, data, activity, undo}`. Reversible ops store their inverse in `undo.jsonl` (data folder, newest 500), keyed by
  the activity id. `undo <A>` runs the stored inverse once and records an `undid` line.
- Public ops: `task.status`, `task.start`, `task.stop`, `subtask.toggle`, `subtask.add`, `plan.move`,
  `question.ask`, `question.answer`, `comment.add`, `issue.new`, `issue.close`, `issue.link`, `undo`.
  Internal inverses (refused from callers): `queue.remove`, `issue.status`, `issue.links`, `subtask.restore`.
- `task.stop` queues a request: a `queue.json` entry with `op: "stop"`. Its inverse removes the entry.
- `plan.move` lives in `commands.py` (no move function in the WP20 services). It writes `tasks.json` through
  `schema.write_data`, moves within one phase only, and sets `updated`.
- `issue.link` and the issue task-list restore write `issues.json` directly, because the WP20 issue service has no
  call that replaces the task list.
- Locking: the WP20 services take the directory lock themselves, and flock is not re-entrant across descriptors, so
  `run()` holds no outer lock. Each write is atomic under its own lock.
- CLI modules (new): `commands/issue.py` (new, list, show, close, link), `commands/subtask.py` (add, done),
  `commands/ask.py` (ask, ask get, ask wait, ask list, answer), `commands/comment.py` (comment, comments),
  `commands/inbox.py`, `commands/budget.py` (show only), `commands/undo.py`.
- `ask wait` polls every 5 s, takes at most 1800 s, and accepts an injected sleep and clock. A question with a
  timeout is defaulted by `questions.expire` during the wait.
- `commands/plan.py`: `plan view` (at most 15 lines) and `plan move <id> --before|--after <id>`.
- `commands/status.py`: adds the `ask:`, `queue:`, `issues:` and `budget:` lines. Priority: header, left, phase,
  run, the four new lines, you, next. Output stays within 8 lines and 700 characters.
- `commands/job.py` and `services/jobs.py`: `job start --parent ID --role lead|worker` (role needs parent; the parent
  must exist). `job done --tokens K` calls `budget.record_job_spend` once per job id.
- `roadmap/cli.py`: COMMAND_MODULES gains issue, subtask, ask, comment, inbox, budget, undo.
- Not done here: `task done|start|hold --tokens` still does not feed the budget, and the task CLI does not go through
  `run()`, so task status changes made from the CLI are not logged or undoable. Both need `commands/task.py`, which
  is outside this package.
- Tests: `tests/unit/test_commands_service.py`, `tests/unit/test_cmd_{support,ask,issue,budget,status}.py`.
