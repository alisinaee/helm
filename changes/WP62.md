# WP62: project new --research, job progress

- `roadmap project new <path> [--name N] [--research]` (commands/project.py, new subcommand only): init the folder, register it (reused when already registered), write `roadmap/templates/plan_template.json` into tasks.json when tasks.json has no phases or tasks (phase P1, `approved: false`), and with `--research` create note 01 `scope` from `research_note.md`. Safe to run again: nothing existing is replaced. Exit codes and the `--json` envelope follow the other project actions.
- `roadmap job progress <id> --tokens K` (services/jobs.py `progress_job`, commands/job.py `_progress`): sets `progressK` and the live `tokensK` on a running job. Only the new part goes to the budget, under the key `<id>@<K>`. A reading that does not move records nothing. A lower reading, a finished job or a bad number is refused.
- `job done --tokens K2` now adds `K2 - progressK` to the budget (never below zero) and refuses a total below the progress already counted (usage, exit 2, job still running). Without `--tokens`, the counted progress stays. Behaviour without progress is unchanged.
- Tests: tests/unit/test_project_new.py (10) and tests/unit/test_job_progress.py (18, including the no-double-count cases).
- docs/API.md: one sentence on a running job's `tokensK` in the snapshot.
- Not in this change (outside the allowed files): `status` does not print "research 1/1 open, phase P1 not approved", and `task start` does not refuse an unapproved phase. Both need edits to services/tasks.py / commands/status.py.
