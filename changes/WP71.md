# WP71: workflow graph model and layout (diagram A)

- New `web/js/graph/model.js`: `buildGraph(snap, filters)` turns a snapshot into `{nodes, edges, lanes, stats}`. Node kinds are phase, task, job pill, issue, queue and collapse. Edge kinds are dependency (`after`), handoff (job to job) and blocker (issue to task). Filters are status, agent and phase, plus `expand` to skip the collapse. Above 300 nodes, the done tasks of each completed phase fold into one `Phase Pn: k done` node. Jobs past 3 show the newest 2 plus a `+n` pill.
- New `web/js/graph/layout.js`: `layout(graph, mode, range, now)` returns `pos`, `paths`, `lanes`, `width`, `height`, `cycles`, `ticks` and `nowX`. Dependency mode ranks columns by longest path. Time mode buckets columns by range. Four barycenter sweeps order each lane. Fixed 168x44 nodes, 36x20 job pills. Cycles are broken by a depth-first search and reported.
- Both modules are pure: no DOM, no clock (`now` is an argument), no randomness.
- New fixtures in `tests/fixtures/graph/`: empty, chain, fan-in, with-blockers, cycle and 350-tasks.
- New `tests/web/render_graph.mjs` (node renderer) and `tests/web/test_workflow_graph.py` (18 tests, skipped without node). They cover determinism within and across runs, no overlaps within a lane, boxes inside lane bands, every edge with a cubic path, the 350-task cap (362 nodes before, 117 after), the cycle, the empty fixture, the filters, `+n` pills, blocker placement and the queue column.
- Not in this change: no view wiring (WP70-B), no CSS, no edits to existing `web/**` files.
