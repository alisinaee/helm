# WP51: plan format F and L records

- planfmt: `F <id> <-|hold> <1|2|3> <phase|-> <parent|-> | title # acceptance` (full set of fields; `-` = none),
  `L <featureId> <taskId>...`, and the `f:<ids>` token on T lines (before `|`, after `a:`). `format_feature` added.
- tasks.apply: F lines and L lines are validated with the tasks in one pass (all or nothing). Feature storage is one
  private helper pair, `_features_load` / `_features_write`, on docs/features.json (schemaVersion 1, store.atomic under
  the directory lock). `load_features` is public for export. WP52 can replace the helper.
- Caps: 3 feats per task, 60 features, parent is top level only, phase and parent must exist.
- Diff summary counts features as `+F` and `~F`.
- The unknown-record message keeps its old text and appends "(also: F, L)", so existing tests still pass.
