# WP29: right panel

- `web/js/views/panel.js`: the `<aside>` with two tabs (Projects, Details) and a Close button. The tab follows the saved
  choice, except that a new `/i/<item>` opens Details once. Esc with an item selected goes back to Projects (and stops
  there, so the sheet stays open). j and k move between the project rows. All writes come from delegated handlers on
  `#side` and go through `cmd.js` `run()`.
- `web/js/views/projects.js`: All projects first, then one row per project. Rows sort needs-you, running, then the rest.
  Each row has a status dot with its word, a progress meter, and badges for open questions, open blockers and running
  jobs. Questions and blockers show only for the project whose snapshot is loaded. A blocked project shows "Locked".
- `web/js/views/details.js`: task view (status, Start and Stop, cap, subtasks, comments, linked issues, questions and
  jobs, rules and definition of done when the snapshot has them), issue view (close), question view (answer), and the
  project card when nothing is selected. Pending values come from `pendingValue()`; comments in flight are held briefly.
- Write ops used: task.status, task.start, task.stop, task.cap, subtask.toggle, subtask.add, comment.add,
  question.answer, issue.close. All are registered (`subtask.add` exists, so nothing is "CLI only").
- `web/js/state.js`: the snapshot keeps subtasks, cap (read from `budget.tasks[id].limit`), definition of done, comments,
  queue and rules. `web/js/app.js`: the `side` section and `initPanel()`.
- `web/css/panel.css` (budget 4.5 KB). On phones the panel is a sheet above the scrim.
- Tests: `tests/web/test_panel.py` with `tests/web/render_panel.mjs` (node render of the views with the golden snapshot),
  the CSS budget, and a check that every op the panel sends is registered. `tests/web/test_shell.py` no longer treats
  panel.css as a stub.
- Not done: Enter needs no binding (the rows are links, so Enter follows them). The sprite has no lock glyph, so the
  blocked mark is text.
