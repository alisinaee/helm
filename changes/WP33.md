# WP33: tokens, limits, rules, settings

- Tokens (`web/js/views/tokens.js`): Today and This week meters for the scope, read from `meters.limits`. Each shows used, limit, the 80% warning tick, a pace line ("At this pace: limit reached about HH:MM" or "Won't reach today") and a grey "unknown" state. The weekly meter has a "today started here" tick. Then the limits editor, the account card (reuses `usage.js`), spend, the override (1-4 h, project scope only) and an accuracy note with a short explainer.
- Limits editor (`web/js/views/limits.js`): one row per limit with window, unit ("% of weekly" or "tokens"), ± stepper with a 0-100 slider (number field for tokens), Stop or Warn, a live preview, and Delete. "+ Add limit" offers the presets "Stay under 10% a day", "Weekly 60%" and, in global scope only, "Daily for all projects". Read-through rows (autonomy.json, budget.json) are read-only. Phone: each row opens as a bottom sheet.
- Ops: `limit.set`, `limit.rm`, `budget.set` (project, phases, models), `task.cap`, `control.override`, `rules.add`, `rules.rm`, `rules.sync`. All go through `cmd.js` `run()`, so refusals show an error toast and undoable changes get an Undo toast.
- Rules (`web/js/views/rules.js`): tabs (All, Lead and worker, Models, Phase and task, Claude), a Delete per rule, an add form with scope, kind and a 160-character counter, and Sync to CLAUDE.md with a backup note. Rules belong to one project; All projects shows a pointer to a project.
- Settings (`web/js/views/settings.js`): theme, density, what a phone may change, keyboard help and where the data lives.
- `web/js/routes.js` registers the three modules. `web/js/app.js` dispatches the new actions (`limitAction`, `ruleAction`, `settingsAction`) and re-renders. `web/js/state.js` keeps the rule kind and value, and the meter row's `action`.
- `web/css/admin.css` is 3.5 KB or less, token-only.
- Depends on the snapshot carrying `meters.limits[].action` and `rules` (the list shows "Rules are not in the snapshot yet" until it does).
- Tests: `tests/web/test_admin.py` checks the files, imports, budget, token-only colours, inline markup and, with node, renders the four views from a synthetic snapshot.
