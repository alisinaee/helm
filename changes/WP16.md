# WP16.1: plan format and tasks service

- `roadmap/core/planfmt.py` (pure, stdlib only): `parse_plan(text)` returns `(records, errors)` for the phase and task lines in docs/AGENT-INTERFACE.md section 2. Every error is `line N: <problem> (allowed: ...)`, and parsing continues past bad lines. Duplicate ids inside one input are errors. `extract_block(md)` returns the first fenced block tagged `roadmap-plan` and skips other fences whole. `parse_set_line` and `parse_set_text` read the bulk `key=value` lines (shlex quoting, `note=""` clears a note, `-` keeps the value). `format_task` and `format_phase` print plan lines that parse back to the same values.
- `roadmap/services/tasks.py`: `load`, `get`, `query(phase, status, needs_you, limit)`, `apply(data_dir, records, dry_run, replace_phase, project_id)` and `summary(data_dir, jobs, name)`. `resolve(project_id)` wraps `jobs.resolve_project`. `apply` runs under `store.lock.locked`, validates every record before the first write (all or nothing; `PlanError` carries the errors, exit 3 when every error is a missing id, otherwise exit 2), and writes through `schema.write_data("tasks")`. It upserts by id, sets `updated` to today only when something changes, recomputes touched phases (all done, then done; any started, then partial; else todo; hold phases are left alone), backs up `tasks.json` when more than 10 tasks change, and removes tasks only for `replace_phase`. A second identical apply changes nothing and writes nothing. New tasks use the canonical field order and keep unknown keys and key order on update. `describe(diff)` gives the `would:` / `wrote:` / `0 changed` line.
- `roadmap/errors.py`: `RoadmapError` takes an optional `next=None` and stores it as `.next`. Existing callers are unchanged.
- Tests: `tests/unit/test_planfmt.py` (grammar, errors, `-` semantics, bulk lines, fenced block, round trips) and `tests/unit/test_tasks_service.py` (idempotency with a fixed mtime, all-or-nothing, key order, phase recompute, replace_phase, backups, no schema bump, query, summary budget, resolve).
- Not changed: the tasks.json schema stays at 1, and no web, http, jobs, hooks or store code was touched.
