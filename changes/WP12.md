# WP12: docs and skill draft

- `README.md` rewritten for the new product: install (clone, `make check`, link `bin/roadmap`), quick start with a
  project, plan usage with an honest account of the keychain prompt and the data sent, hooks, command reference,
  phone access (marked as not built yet), troubleshooting by `roadmap doctor` message, migration from
  `tools/roadmap-web`, exit codes and uninstall.
- `docs/ARCHITECTURE.md`: layers and the lint rule, directory layout, where files live on disk, the config and
  project settings, schema versions and migrations, atomic writes and locks, services, HTTP pipeline, web render
  pipeline, service setup, error handling.
- `CONTRIBUTING.md` (repo root): `make check`, `check-ui` and `check-all`, what the lint checks, rules (no
  dependencies, Python 3.9, layering, `ROADMAP_HOME` in every test), definition of done, change fragments, how to add a
  command, route or detector.
- `docs/API.md` finalized: every `/api/v1` route with a real reply, the error shape and status table, ETag and `304`,
  the write rules in their check order, headers, pages, access log, and the deprecation of `/data.json`.
- `docs/SECURITY.md` draft: assets, threats, controls built and planned, known limits, reporting, and the
  `## Review checklist (WP13/R1)` section left open for the review.
- `CHANGELOG.md` (Keep a Changelog): `[Unreleased]` merged from the fragments WP1 to WP11. The fragments are kept.
- `docs/skill-draft/SKILL.md`: the rewritten `roadmap-dashboard` skill for the new product, with the same name and
  trigger description. It is a draft in the repo; it is not installed into `~/.claude/skills`.
- `tools/check_docs.py`: runs every `roadmap` line in the shell blocks of the docs against a temporary home and a
  fixture project. Unknown commands, crashes, error envelopes and `--help` failures fail the check. Commands that
  touch launchd, the keychain, the network, a live port or stdin run with `--help` only.
- `tests/unit/test_docs.py`: runs the docs check (picked up by `make check`), and tests the extraction, the help-only
  list and the failure rules.
