# WP34: agents, research, notes route, question undo

- Agents (`web/js/views/agents.js`): the running jobs as a tree. A worker (a job whose `parent` is a running job) sits in a nested list under its lead, with its role. Each row shows a model chip, role, task link, elapsed time (ticked every second in the page from the start time), tokens so far, a blocked badge when its task is blocked, a "handed to" chip for a lead, and a Stop button (op `task.stop`; disabled for a job with no task). The last 10 finished jobs follow, with duration, status and tokens. Empty state: "No agents running.". The swimlane timeline is LATER.
- Research (`web/js/views/research.js`): the project's notes from `GET /api/v1/projects/{id}/notes`, a Reload button, and a plain-text reader (escaped and preformatted, never markdown). The onboarding checklist (register, import the plan, set rules, approve phase 1) ticks from the snapshot. The empty state shows the `roadmap research new` step. All projects asks for a project.
- `GET /api/v1/projects/{id}/notes` and `.../notes/{name}` (`roadmap/http/routes.py`, one route entry and its handler): read only. Names must match `NN-slug.md`; symlinks are never followed; files over 64 KB give 413 (listed with `lines: null`); bad names 400; missing notes and unregistered projects 404. Documented in `docs/API.md`.
- Question undo: `question.answer` now returns an inverse, the internal op `question.reopen` (`roadmap/services/commands.py`, `roadmap/services/questions.py`). Undo sets the question open again and clears its answer; a blocking question waits again (`ask wait` reads the open status). Reopening an open question is a conflict.
- `web/js/state.js`: the job normalizer keeps `parent` and `role`. `web/js/routes.js` registers both modules. `web/js/app.js` routes `agent-stop`, `note-open` and `note-refresh`, and redraws on the `rb:render` event that the research requests send.
- `web/css/flow.css`: 4090 bytes in total (the new Agents and Research rules are about 0.8 KB).
- Tests: `tests/api/test_notes.py` (route, traversal, symlink, size, names, missing, Host), `tests/unit/test_question_undo.py` (answer undo, blocking wait, undo record, conflicts, internal op), `tests/web/test_agents.py` with `tests/web/render_agents.mjs` (node renders, nesting, Stop, last 10, escaping, checklist, data-action wiring, budget).
- `tests/web/test_shell.py`: the registry check now asserts the loader's null guard, because no section is unbuilt after WP34.
