# WP72: workflow diagram renderer and viewport

The Map view of the Workflow section is now the diagram of WP71 (`graph/model.js`, `graph/layout.js`), drawn as SVG by
`graph/render.js` and moved by `graph/viewport.js`. The Timeline and Table are unchanged.

- `web/js/graph/viewport.js`: pure gesture state machine (one pointer pans, two pinch, wheel zooms at the cursor, a
  pointer that moves 6 px or less is a tap, two taps within 300 ms zoom 2x), zoom clamped to 0.25 to 3, keys (+ - 0,
  Shift+arrows pan, arrows move focus to the nearest node, Escape clears), and the DOM binding with pointer capture.
  The transform is an SVG `transform` attribute on the viewport `<g>`.
- `web/js/graph/render.js`: builds the SVG with `createElementNS`. Geometry is attributes, colour is classes, the hatch
  pattern is defined once in `<defs>`. Every focusable node is `<g role="button" tabindex="0" aria-label>`. Focus mode
  (`closureOf`, `applyFocus`) dims everything outside the upstream and downstream closure by toggling classes.
- `web/js/views/workflow.js`: `mapSvg` replaces the WP48 phase-column Map. The controls (- + Fit 100% Focus off), the
  order toggle (Dependency | Time), status, agent and phase chips, the "n of m nodes" chip, the "Show all (slow)" note,
  the empty state and the no-match state are in the markup. `graph/*.js` is imported with `import()` in `loadGraph`,
  only on the Map, and a synthetic `hashchange` re-renders once it has loaded.
- `web/css/graph.css` (3.1 KB, tokens only), linked from `web/index.html`.
- `tests/web/test_workflow_diagram.py` and `tests/web/render_diagram.mjs`: 20 tests (source grep, CSS budget, node
  gesture and key checks, SVG aria and no-style checks over the WP71 fixtures).

Decisions and deviations from the spec:

- The view is `#/p/<id>/workflow/map`, not `?v=map`, because that is how the router already works.
- The map filters are tokens inside `f=`: `f=range:today,ord:time,st:doing|blocked,ag:haiku,ph:P2,all:1`. The router
  keeps only the `f` and `g` params, so `?st=&ag=&ph=` needs `FILTER_KEYS` in `router.js` (not in this package).
- A tap on a node selects it (focus mode) and opens its Details, as the old click did. Escape and a background tap clear
  the focus. Escape with Details open goes back to Projects (`panel.js`), so focus follows the route: no item, no focus.
- On open the diagram fits its width at no more than 1:1 and no less than 0.6:1. The Fit button fits both axes, down to
  0.25:1. A wide time layout is panned, not shrunk.
- The Map on the all-projects route shows "Open a project to see its diagram". Timeline and Table still list every project.
- CSS classes are namespaced (`wfg-*`) because `s-done`, `m-opus` and `dim` are already used by other views.

Checks run:

- `python3 -m unittest tests.web.test_workflow_diagram`: 20 OK.
- Full suite (1584 tests): 2 failures, both caused by this change and both in files outside the package (see Not covered).
- Browser (127.0.0.1:8806, temp ROADMAP_HOME, alpha fixture): dispatched touch and mouse PointerEvents: pan 40 px moves
  the transform and does not navigate; pinch doubles the scale; wheel zooms out at the cursor; tap on a task opens its
  Details with focus; Escape and background tap clear the focus; arrows, + - 0 and Shift+arrows work; no CSP violation
  events; no `style` attributes in the SVG; every node has an aria-label. A timeline load requests no `graph/*.js`; the
  Map requests the four modules. The empty project shows the empty state.
- Screenshots (headless Chrome, dark and light, 1440 and 500 px) read for alignment and legibility: the phase label, the
  right-aligned done/total and tokens columns, the cards and pills line up. On a phone the controls sit above the diagram.

Not covered:

- `tests/web/test_workflow_view.py` (WP48) renders the old `mapSvg(model, {stacked})`, which this change replaces, so its
  `setUpClass` and every test that reads the harness now error. Its Map assertions need rewriting for the new Map (the
  file is outside this package).
- `tests/web/test_assets.py` `EXTERNAL` flags the SVG namespace literal in `render.js`. The namespace is an identifier,
  not a host; the test needs an exemption for `http://www.w3.org/2000/svg` (outside this package).
- `tools/ui_smoke.py` fails on a different set of non-workflow routes from run to run (overview, work tree, all tokens),
  with empty-main symptoms; it looks like timing under concurrent smoke runs.
- Focus mode in a real browser was checked through the classes it sets, not in a screenshot (focus needs a tap).
