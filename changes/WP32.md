# WP32: roadmap lanes and issues

- `web/js/views/roadmap.js` (new): Roadmap, project scope. Lanes (default): one lane per phase with progress, estimated tokens, spent tokens, budget, and an Approve button (`phase.approve`). Task cards show status glyph and word, model, size, and a Blocked badge when an open blocker names the task. Timeline view (`#/p/<id>/roadmap/timeline`): one bar per phase in plan order, width proportional to the estimate, spent part filled, no dates. Reorder: native drag within a phase, Up and Down buttons, and Alt+ArrowUp / Alt+ArrowDown on a focused card; all end in `plan.move`. Phone: lanes stack and fold (`lane:<id>` prefs).
- `web/js/views/issues.js` (new): new-issue form (title, task link, blocker toggle; `issue.new`), filters Open / Blockers / All (`?f=`), one-click Close (`issue.close`), title links to `#/p/<id>/issues/i/<I n>`.
- `web/css/plan.css`: lanes, cards, timeline, issues and the form. Token-only, 3.4 KB.
- `web/js/views/overview.js`: restores Phases (with an Open Roadmap link), Next up, Recent progress, Extras and Legend, each as a section header from the existing modules.
- `web/js/routes.js`: registers the Roadmap and Issues modules.
- `web/js/keys.js`: Alt+arrow bindings (`bindKey("Alt+ArrowUp")`), dispatched before the Alt guard.
- `web/js/app.js`: one branch for `plan-move`, `phase-approve` and `issue-close`, which load their module and call `pageAction`.
- `web/js/state.js`: phases gain `approved`; snapshot gains `budget` (per-phase spent and limit); issues gain `sev`.
- Tests: `tests/web/test_plan.py` and `render_plan.mjs` (node render of both views and the restored Overview). `test_shell.py` checks plan.css rules instead of the old stub size.

Known gaps:
- `plan.move` moves only within one phase, so a drag onto another lane shows "A task moves only within its own phase." Cross-phase moves need a server change.
- The snapshot carries open issues only, so the All filter does not list closed ones. The page says so.
- `roadmap plan view` prints no approval marker, so approval shows in the UI only.
