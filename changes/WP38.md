# WP38: end-to-end integration tests

- `tests/integration/` (new package): `harness.py` holds a `Sandbox` (temp ROADMAP_HOME, temp HOME, a temp project
  copied from `tests/fixtures/splitnet` and registered through the CLI) and a `Server` (`bin/roadmap serve --port 0
  --no-usage-loop --no-phone --json` in a subprocess; the port is read from the envelope line; it is always terminated).
  Every subprocess gets a fresh environment; `CLAUDECODE=1` is set only for agent-style calls.
- Flows: `test_question_flow.py` (blocking ask, GUI answer, `ask get`/`wait`, activity lines, undo),
  `test_stop_flow.py` (GUI stop and resume, hook denies and allows, agent shell refused with exit 4 and `next:`),
  `test_limits_flow.py` (warn at 80%, block at 100%, sentinel, budget fed once, override, stale usage fails open),
  `test_task_lifecycle.py` (plan import, start/done with `--tokens` via CLI and /cmd, status size, subtasks, blocker
  issue, comment), `test_http_security.py` (421, 403, 413, 404, 429, notes traversal, phone listener 405/401/503),
  `test_rules_flow.py` (add, show, sync twice: `+2 ~0 -0` then `+0 ~0 -0`).
- Suite time: about 18 s for the 22 tests. No sleeps. Each test runs in its own temp root.

## Real bug found

- Agent-shell writes are logged with source `cli`, not `agent`. `commands.write` hard-codes the source:
  `roadmap/services/commands.py:589-590` (`context("cli", ...)` and `run(op, payload, "cli", data_dir)`). Control ops
  use `agentguard.source_name()` and log `agent`, so the activity line for an agent's `roadmap ask` says `cli`.
  Covered by `tests/integration/test_question_flow.py::test_agent_shell_writes_are_logged_with_source_agent`, marked
  `@unittest.expectedFailure`. Fix belongs in roadmap/ (out of scope for WP38): use `agentguard.source_name()` there.
