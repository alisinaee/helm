# WP13: security hardening

- Phone listener on `127.0.0.1:8766` (`phonePort`): read-only (GET only, POST gives 405), 503 without a usable
  `phone.token`, 401 on a wrong token, `?k=` accepted once and then a 302 that strips it and sets the cookie. The cookie
  holds `HMAC(token, "cookie")`, with `HttpOnly; Secure; SameSite=Strict; Path=/`, seven days. Failed attempts are
  limited to 10 a minute per process, then 429. Every comparison is `hmac.compare_digest`.
- Phone Host allowlist: the loopback names, plus the tunnel host saved as config `phoneHost`, never taken from a request.
- `roadmap phone start|stop|link|status`: start rotates the token (`secrets.token_urlsafe(32)`, mode 0600, atomic) and
  runs `ssh -o ServerAliveInterval=30 -R 80:127.0.0.1:8766 nokey@localhost.run`; stop signals only a pid whose command is
  our ssh to localhost.run and deletes the token. `--json` envelopes and exit codes 3, 4 and 6 as in the spec.
- `roadmap open` module (`commands/open.py`) opens `http://127.0.0.1:<port>/` through an injectable runner. It is not
  registered yet, because the stub is still added by `commands/serve.py`.
- Security review: `docs/SECURITY.md` has the R1 checklist table (requirement, file and line, test, status). The redaction
  audit covers usage sync, phone start and stop, the HTTP server with a `?k=` request, and a static scan of every print
  and log call in `roadmap/`.
- Open gaps, listed in the checklist: `roadmap serve` does not start the phone listener yet; `open` is not registered yet;
  the stderr log handler of `serve` has no redaction filter. These sit in files outside the WP13 list.
