# WP31: work board, list, tree

- `web/js/views/work.js` (replaces the placeholder): the Work section for one project. View switch (Board, List, Tree), filters (`f`) and grouping (`g`) in the hash, view, sort and phone column saved per project in `rb.ui.v2` under `work.<id>`. Clicks, changes and the bulk bar are handled here; every write goes through `cmd.js`.
- `web/js/views/board.js`: shared task helpers (status columns Todo, Doing (state `partial`), Hold, Done; deferred tasks are hidden), filter tokens, the card (id, title, model, needs-you and blocked chips, token meter, subtask and comment counts), quick actions Start, Done, Hold, Reopen and a More menu. Keys `s d h x` set the focused card's status; Alt+Up and Alt+Down move it one column. On fine pointers a card can be dragged to a column (native HTML5 drop, outline `--drop`).
- `web/js/views/list.js`: dense table (checkbox, id, title, phase, status, model, est, spent, cap, flags), sortable headers, group by phase, status or model, and a bulk bar (Set status, Start, Stop) that applies one batch with one Undo. Phone shows two-line rows with no checkboxes or bulk bar.
- `web/js/views/tree.js`: phase, then task, then subtask checkboxes (`subtask.toggle`). Phase rows fold (`toggle-item`).
- `web/js/cmd.js`: `runBatch(items, opts)` added. It posts ops in turn, shows one toast ("N tasks updated") and one Undo that reverts every undoable op, newest first. The bulk bar needs it because `run()` shows one toast per op.
- `web/js/state.js`: `normalizeTask` keeps `spentK` (from the budget row) for the List spent column.
- `web/css/work.css`: 4.7 KB, tokens only. Shared CSS total is 52214 bytes, just under the 52224 limit.
- `web/js/routes.js`, `web/js/keys.js`, `web/js/app.js`: no change needed (the `work` route and the key bindings are registered from the view modules through `bindKey`).
- Tests: `tests/web/test_work.py` renders Board, List and Tree in node (`tests/web/render_work.mjs`) from the golden snapshot plus a temporary copy with subtasks, a blocker, a comment and a budget row. It checks card, row and subtask counts, the flags and meter, the grouping, aria-controls, no inline style or handlers, the sort and filter helpers, the `work.css` budget, and that the four modules are lint clean. `test_shell.py` now checks `work.css` for real rules instead of the 400-byte stub size.

Known gaps and conflicts:
- The Undo toast lasts 5 s, so a test has to click Undo inside that window.
- A card's More menu closes when the section re-renders (a `<details>` element), so a poll that changes the page closes it.
- Checkbox focus blocks re-rendering of the section (dom.js rule). Selection and subtask checkboxes refocus after their change, so the bulk bar updates on the change itself.
- Scripted `.click()` does not move focus, so checkbox clicks scripted in quick succession can miss the update. Real clicks behave correctly.
- `subtask.add` is not wired (no add field in the Tree view), so the CLI-only hint from the spec is not shown.
- Other packages' tests still fail in the shared tree: the `<label>` checks (issues.js), the h1 count (issues.js, roadmap.js, topbar.js), and `plan.css` (3441 bytes, not a stub). None of these are WP31 files.
