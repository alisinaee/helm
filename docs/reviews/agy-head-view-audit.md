# Head View Audit: ARIA, Keyboard, Row Alignment, and Plain-Words Strings

| file:line | issue | fix |
|---|---|---|
| web/js/views/head.js:225 | `headerHtml()` returns `<div class="row-grid hd-row hd-head rg-head">` rendered directly as a child of `<ul class="hd-list">` (line 251), violating semantic HTML and ARIA required child hierarchy for lists. | Render `headerHtml()` outside `<ul class="hd-list">` immediately preceding it, or wrap the header in an `<li class="hd-head-item">`. |
| web/js/views/head.js:174 | `aria-label` is hardcoded to `"Accepted, " + id` even when `acc` is false (`aria-checked="false"`), causing screen readers to announce unaccepted items as "Accepted, [id], not checked". | Set label dynamically based on state: `(acc ? "Accepted, " : "Accept ") + id`. |
| web/js/views/head.js:184 | Chevron button toggle (`head-toggle`, line 288) updates `aria-expanded` in line 292 but never updates `aria-label`, leaving it permanently fixed at initial render state ("Show [id]" or "Hide [id]"). | In line 292, update `btn.setAttribute("aria-label", (panel.hidden ? "Show " : "Hide ") + id)` alongside `aria-expanded`. |
| web/js/views/head.js:218 | Expand text button (`data-action="head-text"`) lacks `aria-expanded` and `aria-controls` attributes, and click handler (line 295) toggles text expansion without updating button state. | Add `aria-expanded="false"` and `aria-controls="hd-t-[id]"`, and toggle `aria-expanded` and button text between "Show all" and "Show less" on click. |
| web/js/views/head.js:192 | Stale/aging warning state is conveyed by colour alone (`.hd-amber` with no text, title, or icon, and `.hd-stale` with only hover title), violating UI checklist rule 1 ("status never by colour alone"). | Add visible icon or text badge (e.g. `title="Aging (>30m)"` and warning icon) so stale/amber status is accessible without colour. |
| web/js/views/head.js:149 | Bound reference chips are rendered as static `<span>` elements without `href`, `role="link"`, or keyboard focusability, failing HEAD-SPEC §5 line 138 ("each linking to its section"). | Render chips as `<a>` links with `href` targeting `#work?task=...` or `#issues?id=...` so keyboard users can navigate to linked entities. |
| web/js/views/head.js:176 | `<details class="hd-more">` popup menu lacks keyboard dismissal on `Escape` and does not close after selecting an action in lines 300-302 (`head-set`), trapping keyboard focus. | Add document `keydown` listener to close details on `Escape`, and set `details.open = false` upon executing menu actions. |
| web/js/views/head.js:131 | Search input specifies `placeholder="/ search"`, implying a global `/` keyboard shortcut, but no keydown handler for `/` exists in `attachHeadListeners()` (lines 277-314). | Add `keydown` handler in `attachHeadListeners()` to focus search input when `/` key is pressed outside active form controls. |
| web/js/views/head.js:174 | Accept control uses `role="checkbox"` but invokes `head.accept` (line 296), which is an irreversible one-way action that cannot be unchecked with keyboard `Space`. | Use button semantics (`role="button"`) for one-way confirmation, or support unchecking via undo/status reset if checkbox semantics are kept. |
| web/css/head.css:3 | Column 1 track is fixed at `24px` in `.hd-row.row-grid`, but `.hd-chev` button has explicit `width: 32px` (line 9), overflowing track 1 into track 2 and misaligning data rows with header columns. | Set `.hd-chev { width: 24px; }` or adjust column 1 track to `32px` across all grid definitions. |
| web/css/head.css:4 | Selector `.hd-row .ref-copy` targets nested descendant inside `<span class="hd-c hd-copy">` (head.js line 196) rather than grid item `.hd-copy`, preventing grid column placement on the grid child. | Change CSS selector to `.hd-row > .hd-copy{grid-column:10}` (or `.hd-copy{grid-column:10}`). |
| web/css/head.css:5 | Direct grid child `<details class="hd-c hd-more">` (head.js line 176) inherits `.hd-c` (`overflow: hidden; white-space: nowrap`) inside a 32px track, and `.hd-menu` lacks positioning styles, causing menu popup to clip invisibly inside 32px. | Remove `hd-c` from `<details>`, set `.hd-more { position: relative; }`, and define `.hd-menu { position: absolute; right: 0; z-index: 10; background: var(--bg-1); }`. |
| web/css/head.css:9 | `.hd-chev` and `.hd-acc` buttons have `32px` dimensions across all screen sizes, violating UI checklist rule 2 touch target requirements (`>= 44x44 px` on phone). | Add `@media (max-width:599px) { .hd-chev, .hd-acc { min-width: 44px; min-height: 44px; } }`. |
| web/css/head.css:16 | Mobile responsive rule wraps row into 4 flex lines instead of collapsing into two lines with right-aligned numbers and actions as required by UI checklist rule 0 and HEAD-SPEC §5 line 147. | Refactor `@media (max-width:599px)` flex order and widths to collapse row to 2 lines, keeping age and action buttons right-aligned. |
| web/js/views/head.js:299 | Reopen action passes `set: { status: "open" }`, which is an invalid status string not defined in HEAD-SPEC §2 line 37 or `STATUS_WORDS` (line 16), breaking state rendering. | Set a valid status string recognized by HEAD-SPEC and `STATUS_WORDS`, such as `{ status: "new" }` or `{ status: "understood" }`. |
| web/js/views/head.js:228 | Header columns use terse abbreviations `"S"` and `"Acc"` without `title` or `aria-label` attributes explaining "Session / Account" and "Accepted". | Add plain-words title and aria-labels: `<span class="hd-c" title="Session or Account">S</span>` and `<span class="hd-c" title="Accepted">Acc</span>`. |
| web/js/views/head.js:117 | Filter dropdown default option text is hardcoded to lowercase string `"all"` (head.js lines 133, 135) instead of plain-words labels `"All kinds"` and `"All sessions"`. | Pass `"All kinds"` and `"All sessions"` as `allText` argument to `optionsHtml()`. |
| web/js/views/head.js:159 | Status chips for `doing` and `needs-you` render text without icons (only `done ✓` has an icon), violating HEAD-SPEC §5 line 139 ("The status chip carries text and an icon, never colour alone"). | Add accompanying icons/symbols to all status strings (e.g. `doing ⟳`, `needs you ⚠`, `bound ⚯`). |
| web/js/views/head.js:175 | Icon glyphs (`☑`, `☐`, `▾`, `▸`, `↺`) are rendered as raw Unicode text characters rather than SVG sprite symbols, violating UI checklist rule 7 ("Icons: SVG sprite only, no emoji as icons in the UI"). | Replace raw Unicode glyphs with `<svg class="icon"><use href="web/icons.svg#..."></use></svg>` sprite icons. |
| web/js/views/head.js:76 | Session header line displays developer abbreviation `"prev:"` instead of plain words `"Previous:"`. | Change label string `"prev: "` to `"Previous: "`. |
