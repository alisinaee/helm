# Opus review: v3 S1 supervisor + leases (R7.99, a59d9f9)

Scope: roadmap/services/supervisor.py, roadmap/services/leases.py, db.py schema v3, vs HEAD-V3-PLAN section 3.
Tick and writers both use BEGIN IMMEDIATE, so tick-vs-writer races inside one pass are serialized; finish() refuses non-running jobs, so a late finish after reap cannot double-resolve.

1. HIGH supervisor.py:160-161 - fold never fires for a task that had any failed attempt: retried failed jobs keep status 'failed', so `any(s != "done")` blocks forever even after the retry succeeds. Fix: ignore jobs with `retried_by`/`escalated` (or consider only the latest attempt chain); also ignore 'cancelled'.
2. HIGH supervisor.py:116-125 - retry fires for every failure (explicit `job finish failed`, crashes, test failures); plan allows retry only for reason in {lost, unavailable}. Wrong-cause retries loop work twice. Fix: retry only reaped ("no heartbeat"/lost) and unavailable reasons; other failures -> escalate/needs-you or leave.
3. HIGH leases.py:31,107 + jobs_db - a lease only counts when its job is 'running'; jobs_db.finish (115-135) never calls leases.release, and the plan's claim txn (assert single-flight + leases + insert job) is not done: acquire() is separate from job start. If acquire runs before the job row is 'running' (queued/claimed), two jobs can lease the same file. Fix: wire acquire into the same txn as the job insert/start, release in finish(), and treat queued/claimed owners as live.
4. MED supervisor.py:241 - next_launches treats only 'running' as busy; a job picked/launched but not yet 'running' (claimed) is invisible, so two ticks/launcher calls can pick the same queued job or same task. Fix: launch via an atomic queued->claimed UPDATE ... WHERE status='queued' and count 'claimed' as busy.
5. MED supervisor.py:87 - `float(beat)` raises if any writer stores heartbeat as ISO text; one bad row aborts the whole tick (whole txn rolls back) every 5 s = supervisor dead. Fix: parse via _epoch_of_iso fallback and skip/log bad rows.
6. MED supervisor.py:191-199,215-226 - lock TTL 60 s is not refreshed and released in a separate txn; if the work txn raises, the report var is unbound (finally ok, but `report["ran"]` NameError masks the real error). Lock itself is redundant with BEGIN IMMEDIATE; fine, but crash leaves it for 60 s only (ok). Fix: init report before try or let the exception propagate cleanly.
7. MED supervisor.py:130,136 - backoff is 60/300 s; plan says 2/10 min. Also failed_at falls back to `now` when missing, so a crash-restart keeps pushing not_before forward only once (ok), but ended ISO from routes._now_iso is local-tz aware -> fine; naive ISO strings would be read as local time (acceptable, note).
8. LOW supervisor.py:89 + leases.py:91-100 - reap and drop_expired both use 180 s; a job 60 s late on heartbeat keeps running after its leases are dropped by drop_expired only if its lease ttl < reap ttl. Equal now; keep lease TTL >= HEARTBEAT_TTL_S as an asserted invariant.
9. LOW supervisor.py:158 - fold marks done on any `commit:` ref, including a commit from an earlier unrelated job; plan wants "job done + commit bound". Fix: require the commit ref to be bound to one of the task's done jobs.
10. LOW supervisor.py:98-113 - escalation sets data.needs_you but not the `status` column; queue/next ordering (plan: needs-you second) cannot see it via SQL. Fix: mirror into a column or event-derived view.
11. LOW db.py v3 - leases has no FK/cleanup for deleted jobs; release() only by job_id, so a deleted job's leases linger until expiry (bounded by TTL, not forever).
