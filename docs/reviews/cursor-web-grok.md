Read-only review of the web GUI added in the last two days. No innerHTML in the graph modules (they use `createElementNS` and text nodes). No inline `style=` or event-handler attributes in these files. Copy buttons sit beside links and toggles, not inside them. Highest-severity issues:

1. **High** | `web/js/graph/model.js:106` | A `hold` task is mapped to `blocked` (`model.js:73`) and `currentOf` then treats every non-done, non-deferred task as Now. After any task is done, the first held or blocked task gets the flag, and later todos are dimmed (`render.js:356`). The End label counts those holds as still left (`model.js:345`). Snapshot rules count only `todo` and `partial` as left. **Fix:** choose the first `doing` task, otherwise the first `todo` after the last `done`, and skip `defer` and `blocked`. Count only `todo` and `doing` in `left`.

2. **High** | `web/js/graph/model.js:374` | `current` is computed from the full task list (`model.js:219`), while nodes and the path use the filtered set (`model.js:234`). A status, phase, or agent filter that hides the current task leaves `flow.now` with no box, so there is no halo and Centre-on-Now does nothing (`viewport.js:273`). For the 300-node cap, that missing lane makes `curIdx` `-1` (`layout.js:624`), and the second cap pass then folds every frame (`layout.js:643`). **Fix:** run `currentOf` on the tasks that remain after filters. If that task was folded away, point Now at its phase card.

3. **Medium** | `web/js/graph/model.js:107` | Deferred tasks are omitted from Now and from `left` (`model.js:345`). A chain whose only unfinished tasks are deferred becomes End with "0 left", and the success path runs through those tasks because nothing sits after End. A phase whose non-deferred tasks are all done starts collapsed (`model.js:211`, `model.js:253`), so the deferred tasks are not drawn. Skipping a deferred task when a later todo exists matches the tests. **Fix:** keep Now on the last real todo or doing task when only deferred work remains, and do not fold a phase that still has deferred tasks.

4. **Medium** | `web/js/graph/viewport.js:293` | A glide keeps calling `onView` after the SVG is replaced. `mountMaps` only stops the minimap (`workflow.js:802`) and then mounts with the view captured at render time (`workflow.js:803`). The old animation writes `mapStateFor(pid).view` and the next refresh jumps the camera back. **Fix:** stop the previous viewport (cancel the animation frame and ignore `onView` once the SVG is disconnected) before mounting the new one. Read the live view at mount time.

5. **Medium** | `web/js/graph/viewport.js:368` | `pointermove` calls `paint()` even when that pointer is not down. Each move does `getBoundingClientRect` in `local()` and again in the minimap subscriber. On a 300-node map that forces layout for the whole hover. The Map poll also builds the timeline model every time (`workflow.js:986`) and calls `buildGraph` twice (`workflow.js:707`, `workflow.js:713`). Focus mode walks every edge per node with `Array.shift` (`render.js:69`). No infinite loop in the layout sweeps. **Fix:** paint only while a pointer is captured. Build the graph once. On the Map, skip the timeline model. Walk edges with an index, not `shift`.

6. **Medium** | `web/js/views/tasks.js:212` | The title is `role="button"` (`tasks.js:101`) but only double-click and F2 start an edit. Enter and Space do nothing. Blur always restores the old title and moves focus back to the span, so a click on the neighbouring Copy reference button is lost. **Fix:** handle Enter and Space like a button. On blur, commit or cancel without focusing the span when focus is moving to another control.

7. **Medium** | `web/js/log.js:92` | `scrub` strips `?` and `#` only from `scheme://` URLs, and replaces only the `/Users/<name>` or `/home/<name>` segment. Stacks and `console` text still keep the rest of the path (`~/Works/...`) and any relative query (`/?k=...`). Windows paths are unchanged. Form submits log the form name only (`log.js:346`), and copy-ref logs the ref, not `data-sum`. **Fix:** drop the whole path after the home marker, strip `?…` and `#…` from any string, and redact `C:\Users\...` the same way.

8. **Low** | `web/js/log.js:357` | The console wrapper has no re-entry flag. `record` does not call `console`, so a normal log does not loop. If `String(arg)` or a `message` getter calls `console.error` again, the wrapper recurses until the stack dies. The `catch` then `return`s and the original `console.error` never runs. `failed()` does not log send failures. **Fix:** set a `busy` flag around `record`, and call `original.apply` in `finally`.

9. **Low** | `web/js/log.js:335` | `securitypolicyviolation` always queues another `ui.csp` event. `connect-src 'self'` allows `POST /api/v1/log`, so this does not loop today. If that POST were blocked, each flush would create another violation until the 300/minute cap. **Fix:** ignore a violation whose blocked URI is `/api/v1/log`.

10. **Low** | `web/js/log.js:287` | `flush` starts every batch at once with `keepalive: true`. Each body is under 14 KB, but several batches in flight can pass the browser's 64 KB keepalive cap, so the tail is dropped on `pagehide`. **Fix:** send one keepalive batch on `pagehide` and leave the rest queued.

11. **Low** | `web/js/graph/viewport.js:387` | Wheel over the diagram always `preventDefault`s, so the page does not scroll. Arrow keys are taken as soon as focus is inside the SVG (`viewport.js:394`). Every node is `tabindex="0"` (`render.js:150`), so Tab walks all 300 nodes. **Fix:** keep wheel-zoom for Ctrl/pinch only, and use one tab stop on the SVG with arrow keys moving a roving tabindex.

12. **Low** | `web/js/views/tasks.js:17` | `renamed` is keyed only by task id and expired entries are never removed. The same id in another project shows the other project's title for up to 10 seconds. **Fix:** key by project and task id, and delete the entry when it expires or when the snapshot title matches.

13. **Low** | `web/js/views/details.js:199` | The Run panel puts the absolute project path in `data-cmd` and in the visible command (`details.js:151`). That string is not covered by the log scrubber if it later reaches `console` or an error. **Fix:** show a redacted path in the panel and pass the real command only to the clipboard.

14. **Low** | `web/js/views/workflow.js:440` | Timeline bar and mark classes are concatenated into HTML without `esc()` (`workflow.js:509`). Today `statusOf` and the mark list only emit `doing`, `done`, `blocked`, and `queued`, so this is not exploitable. A raw status would break out of the attribute. Graph nodes are safe: user text goes through `createTextNode` or `setAttribute`. **Fix:** run those class tokens through `esc()`, or keep a fixed class map.
