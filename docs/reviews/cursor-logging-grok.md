Read-only review of the debug logging path. I’ll read the listed modules and the guards around them, then put findings in this chat.

Source is in place. Next I’ll read the logger, HTTP routes, and the emitters that write into it.

The phone listener does not serve or accept the debug log. `PhoneApp.handle` returns 403 for every path that starts with `/api/v1/log` before the token check and before the route table (`roadmap/http/server.py:183`). Those route regexes are exact, so an encoded path does not reach `log_post`, `log_status`, or `log_report` either. Field values cannot forge a second JSON line: `debug_event` writes `json.dumps(...) + "\n"`, and that encoding escapes newlines.

Findings, most severe first:

1. **high** | `roadmap/http/routes.py:148` | Every write refusal appends a `core.guard` line before `log_requests` or `EventBudget` run. A `POST` to `http://127.0.0.1:8780/api/v1/log` with no CSRF and a cross-site `Origin` (a normal browser form or `text/plain` fetch) is enough. Once the 200/min budget is full, each of the 20 allowed requests per second logs another `core.guard` (`routes.py:300`). Those lines are not part of the event budget, so they rotate the 20 MB cap and push real WARN/ERROR lines out. | Count guard lines in `EventBudget` (or sample them), and run that limiter before `_guard_refused`. Keep the 403.

2. **high** | `roadmap/log.py:196` | `_clean_data` replaces the whole `data` object with `{"cut": true}` once its JSON exceeds 1024 bytes. `_clean_stack` is allowed to keep 1500 bytes (`log.py:117`, `log.py:175`). A browser `ui.error` sends `at` plus a stack (`web/js/log.js:319`), so the usual error record is stored with the stack and location removed. | Give the stack its own budget inside the cap, or set the data cap to include `_STACK_CAP`, and drop only the fields that do not fit.

3. **medium** | `roadmap/log.py:389` | `route` and `ref` are redacted and query-stripped, then stored with no `_scrub` and no control-character strip. `data.stack` is redacted and frame-capped, then stored with full paths (`log.py:175`). `core.exc` stores the raw request path (`roadmap/http/server.py:258`). The client copies `location.hash` into `route` with no strip (`web/js/log.js:104`). The report and `roadmap logs` print `route` and `ref` as stored (`roadmap/log.py:540`, `roadmap/commands/logs.py:115`). A newline, CR, or ANSI sequence in `route` becomes extra report lines and terminal control codes; a path such as `/Users/<name>/...` is kept. `msg` is scrubbed, these fields are not. | Run every stored string through `_scrub` and strip characters below U+0020. Do the same again in `_report_line` and `_line`.

4. **medium** | `roadmap/log.py:312` | If `debug-log.json` exists but `open` or `json.loads` fails, the code caches `enabled: true` under that file's inode, mtime, and size. `roadmap logs status --off` stays on disk and the process keeps logging until the file's stat changes. A missing file also defaults to on (`log.py:121`, `log.py:350`). | When the file exists and is unreadable or invalid, keep the switch off and do not cache that fallback. Update the cache inside `_write_settings`.

5. **medium** | `roadmap/commands/hook.py:42` | The deny or allow JSON is flushed, then `_log_event` parses all of stdin again and calls `debug_event`. A deny is WARN, so it always appends and may rotate. The skip uses the presence rule: it returns only when less than 200 ms of the 300 ms budget is left (`roadmap/services/hooks.py:322`), and it does not limit the log call. Exceptions are caught (`hook.py:52`), so logging does not crash the hook. A stalled `open` still holds the process; Claude's hook timeout is 10 s (`roadmap/services/hooks_install.py:20`) and a killed hook drops the deny. | Log only the hook name and decision already known to `run_hook`. Skip the write unless a few milliseconds remain. Do not parse stdin a second time.

6. **medium** | `roadmap/log.py:180` | Denied-key checks run after the key is cut to 40 characters, so a longer key can end in `password` or `token` and still keep its value. `api_key`, `apikey`, and `session` are not in `_DENIED_KEYS` (`log.py:119`). Value redaction is only `Bearer`, `sk-ant-`, and `k=` (`log.py:31`). `token=`, `ghp_`, and `sk-proj-` in `msg` or `data` are stored. `_strip_query` removes `?` and leaves `#fragment`. | Test the raw key against the denylist, add those key names, and redact the common token shapes in values before the cut.

7. **medium** | `roadmap/log.py:546` | The debug file is one global log. `GET /api/v1/log/report` labels the body with the first registered project (`roadmap/http/routes.py:349`) and then prints every project's WARN, ERROR, and `ui.mark` lines. There is no project filter on `read_events`. | Store a project id on each event and filter the report and `roadmap logs` to the project being shown.

8. **medium** | `roadmap/http/routes.py:371` | `GET /api/v1/log/report` and `GET /api/v1/log/status` have no CSRF check and no auth. Any other account on the machine can `curl http://127.0.0.1:8780/api/v1/log/report` while the server is up. Mode 0600 on `debug.jsonl` does not apply to that response. Same-origin browser reads still need the page; cross-origin JavaScript cannot read it (no CORS). | Treat this like the rest of the localhost API in the threat model, or require the same local bound as the files before returning report text.

9. **medium** | `roadmap/log.py:453` | Bad UTF-8 and invalid JSON are skipped per line. `RecursionError` and `MemoryError` are not. They leave `_iter_records` and `read_events` returns `[]` (`log.py:499`), so one nested or huge line blanks `roadmap logs` and the report. | Catch `Exception` on each line and continue. Cap the bytes read from one line.

10. **low** | `roadmap/log.py:257` | `_lock` is in-process only. The server and `roadmap hook` can rotate the same files together, drop a generation, or leave a backup a bit over 5 MB. Symlink slots are refused, and `os.replace` does not follow a symlink, so rotation does not write through one. `_ensure_dir` never forces mode 0700 (`log.py:209`), so umask 022 creates a world-listable directory. `os.open(..., 0o600)` is umask-masked until `fchmod` (`log.py:279`). `open` has no `O_NONBLOCK`, so a FIFO at `debug.jsonl` blocks while holding `_lock`. | Use `fcntl.flock` around append and rotate, `chmod` the directory to 0700, and open with `O_NOFOLLOW|O_NONBLOCK` on a directory fd.

11. **low** | `roadmap/http/security.py:241` | `EventBudget` is one counter per process, shared by every tab and every local client. `take(0)` returns true when the window is already full. The client allows 300 events per minute (`web/js/log.js:170`) and retries a 429 once (`web/js/log.js:267`), which spends another request. `core.write`, `core.exc`, `core.api`, and `hook.event` never take a budget slot. `GET /api/v1/log/report` has no limiter and scans the logs twice. | Reject `n < 1`. Do not retry 429. Put server-emitted lines on the same budget. Cap concurrent report scans.

12. **low** | `roadmap/commands/logs.py:78` | `--since 1d` is 86400 seconds, and the cutoff comparison is absolute, so a DST change does not throw. `--session last` takes the newest event of any level (`logs.py:95`), then applies `--level`, so the session can be one that has no WARN lines. The printed clock is `ts[11:19]` with no zone conversion (`logs.py:110`). A `ts` that `fromisoformat` cannot parse is dropped for the whole filtered query (`roadmap/log.py:473`). | Resolve `last` with the same level and source filters. Format the clock in local time. On a bad `--since` value, exit with a usage error.

13. **low** | `roadmap/log.py:404` | `debug_event` calls `debug_enabled()` and `enabled()` outside `_settings_lock` and `_lock`. `set_enabled(False)` can return and one more line can still be appended. Two processes can also clobber `debug-log.json`; `_write_settings` does not take a file lock. | Re-check the switch inside `_append` and write settings with the same flock as the log.
