Skill is for diff review via a subagent. This gate wants a full-file read of the named modules, so I'll read those sources directly.

The review found seven real bugs. The highest is a project symlink that can copy secrets and overwrite files outside the project when hooks are installed.

1. **High.** `roadmap/services/hooks_install.py:51`, `roadmap/services/hooks_install.py:124`, `roadmap/store/atomic.py:18`, `roadmap/store/atomic.py:48`, `roadmap/store/backup.py:30`. A project can ship `.claude` as a symlink (git stores it). From `~/Work/evil`, a link `.claude` → `../../.claude` is the user’s real `~/.claude`. `roadmap hooks install` reads and then `os.replace`s `settings.local.json` through that link, so it rewrites `~/.claude/settings.local.json` (permissions, env, other hooks). `shutil.copyfile` follows the link, so a `settings.local.json` symlink to a JSON secrets file (for example `~/.claude.json`) is copied into `backups/<project>/<stamp>/` and written back into the project tree. `os.stat` in `atomic._mode_of` follows the link, so the new file keeps the target’s mode (often `0644`). Fix: `lstat` the path, refuse any symlink, and require `realpath` of the settings file to stay inside `realpath(project)/.claude/`. Open with `O_NOFOLLOW`.

2. **High.** `roadmap/services/tunnel.py:159`, `roadmap/services/tunnel.py:196`, `roadmap/commands/phone.py:51`. `find_tunnel_host` returns the first `https://` host in ssh’s stdout that is not `localhost.run` or a subdomain of it. ssh is started with no `StrictHostKeyChecking` and no private `known_hosts`, so the remote banner is trusted. If that banner contains `https://evil.example/` before the real tunnel URL, `phoneHost` becomes `evil.example` and `roadmap phone link` prints `https://evil.example/?k=<phone token>`. Opening the link sends the token to that host. The phone listener then allows `Host: evil.example` as well (`roadmap/http/security.py:58`). Fix: accept only `*.localhost.run` and `*.lhr.life`. Pass `-o StrictHostKeyChecking=yes` and a `UserKnownHostsFile` under the state directory.

3. **Medium.** `roadmap/services/tunnel.py:180`, `roadmap/services/tunnel.py:204`, `roadmap/services/tunnel.py:223`. If ssh exits before a URL appears, `_wait_for_host` already saw `ps` return nothing, then `start` still sends `SIGTERM` to that pid. A reused pid is killed. `is_our_tunnel` is only a substring check (`"ssh"` and `"localhost.run"`). On `phone stop`, `ps` timeout or failure also returns nothing (`roadmap/services/tunnel.py:54`). That path is treated as “not running”: exit 0, token and pid file deleted, ssh left alive. A later `phone start` writes a new token while the old public hostname still forwards to port 8766. Fix: signal only when `ps` still shows this process’s ssh command. If `ps` fails, exit non-zero and keep the pid file. Do not signal a pid that `ps` already reported gone.

4. **Medium.** `roadmap/services/hooks_install.py:135`, `roadmap/services/hooks_install.py:118`. The install locks `.claude` with `flock`. Claude Code does not take that lock. Install reads `settings.local.json`, backs up that snapshot, then replaces the file. A save Claude makes in between (permissions, env, another hook) is overwritten, and the backup does not contain it. Fix: re-read immediately before the replace and merge again if the bytes changed. Write the temp file and `os.replace` only when the inode generation or hash is still the one that was merged.

5. **Medium.** `roadmap/services/launchd.py:146`, `roadmap/commands/service.py:48`. `uninstall` ignores the `launchctl bootout` status, deletes the plist, and returns success. The CLI then exits 0. If bootout failed, the job can keep running (KeepAlive) with its plist gone, so the next bootout has nothing to point at. Fix: treat bootout like `stop` (`roadmap/services/launchd.py:167`): non-zero is failure except “not loaded” (exit 3 and 113). Delete the plist only after bootout succeeds or the job was already unloaded.

6. **Medium.** `roadmap/services/hooks_install.py:20`, `roadmap/services/hooks_install.py:152`, `roadmap/services/hooks.py:209`, `roadmap/store/lock.py:16`. The installed hook is synchronous, with `timeout: 10`. `roadmap hook` holds the state-directory lock and, inside it, `jobs.start_job` waits up to 10 seconds for the project data-directory lock. A busy `jobs.json` lock makes the hook run until Claude kills it. The turn waits on PostToolUse (Agent, Task, Bash) and on Stop. The process dies from the timeout instead of exiting 0, so the “hooks never fail a tool call” guarantee does not hold. Fix: take the project lock with a short timeout (about 1 second), release the state lock before waiting, and on lock failure return immediately so the process can exit 0. Keep the Claude timeout above that budget.

7. **Low.** `roadmap/http/static.py:40`, `roadmap/http/static.py:57`. The allowlist is an exact URL map, but `open(entry.path)` follows symlinks. A symlink inside `web/` whose name has a served extension (`web/note.txt` → phone token, config, or another file) is sent to loopback and, with the phone cookie, through the tunnel. `..` in the URL is not required. Fix: when building the map, use `realpath` and drop any file whose real path is outside `realpath(web_root)`. Open the stored real path.
